# dsh-freebuff 调研报告

> 目标：把 freebuff（CodebuffAI 的免费 AI 编程助手）的免费 DeepSeek V4 Flash 额度，通过 DSH 反代插件变为 DSH 可直接选用的模型提供方（provider）。
> 调研日期：2026-08-17 前后 · 依据源码：freebuff npm 0.0.149、CodebuffAI/freebuff main、freebuff2api-wokers、DSH rc.6 安装包

---

## 0. 结论摘要

- **可行**，且已有社区完整逆向（freebuff2api-wokers，AGPL-3.0 可参考，本插件为其「DSH 原生化」移植）。
- **不要 spawn CLI 二进制**：freebuff CLI 是 Bun 编译的 TUI（无 headless/API 模式），正确做法是在插件内实现 CLI 同款 HTTP 协议，并**直接复用本机 CLI 已登录的凭证**（`~/.config/manicode/credentials.json` 里已有 `authToken`，本机已装 freebuff 0.0.149 且已登录）。
- **DSH 集成点明确**：`ctx.llm` 服务的 `LlmAdapter` 接口（`registerAdapter` + `registerConfigurableProviders`），以 `dsh-llm-deepseek` 为模板实现 `dsh-llm-freebuff`，做成独立插件包，用超级模组注入器装配进 web profile。
- **关键约束**：免费模型需要 **US 出口 IP**（本机代理节点需为美国）；每账号同时只能一个在线实例（必须串行队列）；DeepSeek V4 Flash 在完整模式下为官方非 Premium 模型（无限量分类，受限模式下每天 6 个 1 小时 session）；**反代违反 freebuff ToS，有封号（终态不可恢复）风险**。
- **上游强制流式**：对 DSH 是天然利好——DSH harness 本来就是流式驱动（chat / 会话标题 / 压缩全部走 `stream(options)`），无需像 freebuff2api 那样做非流式聚合。

## 1. 背景：DeepSeek 涨价 vs freebuff 免费额度

- **DeepSeek 官方 2026-08-17 起涨价并改为峰谷定价**：V4-Flash 空闲时段输入缓存未命中 1.5 元/M、输出 4.5 元/M，高峰时段（9:00–14:00）翻倍；V4-Pro 空闲 4.5/13.5 元/M，高峰 9/27 元/M。
- **freebuff（[CodebuffAI/freebuff](https://github.com/CodebuffAI/freebuff)）**：Codebuff 平台的免费版，靠文本广告盈利。模型池含 DeepSeek V4 Flash 07/31、DeepSeek V4 Pro 08/13、GPT-5.6 Luna、MiniMax M3、MiMo 2.5、GLM 5.2（资格解锁）、Gemini 3.1 Flash Lite 等。**没有官方 API**，只有 CLI（npm 包）/ Desktop / chat。
- 社区已验证：完整访问模式下 **DeepSeek V4 Flash 与 MiMo 2.5 是官方非 Premium（unlimited 分类）模型**，是免费主力。

## 2. freebuff 结构：launcher + Bun 二进制 + 官方源码

- npm 包 `freebuff`（当前 0.0.149）只有 4 个文件：`index.js` / `launcher.js` / `http.js` / `README.md`。
- 真实 CLI 是 **Bun 编译的二进制**，由 launcher 从 `https://codebuff.com/api/releases/download/<version>/freebuff-<platform>-<arch>.tar.gz` 下载到 **`~/.config/manicode/`**（本机已存在：`freebuff.exe` + `freebuff-metadata.json` v0.0.149 + **`credentials.json` 已登录** + `settings.json`）。
- 官方仓库（本机已克隆到 `research/freebuff-src/`，1402 文件）含 `cli/`（TUI）、`sdk/`（协议实现 `sdk/src/impl/llm.ts` 等）。**CLI 无 headless 模式**，无法直接 spawn 出 API。

## 3. freebuff 上游协议全貌（代码级逆向，worker.js + 官方 sdk 双重印证）

Base URL：`https://www.codebuff.com`（可被 `NEXT_PUBLIC_CODEBUFF_APP_URL` 覆盖）。鉴权：`Authorization: Bearer <authToken>`。

### 3.1 登录（设备码流，一次获取长期 token）
1. `POST /api/auth/cli/code` `{fingerprintId}` → `{loginUrl, fingerprintHash}`（loginUrl 含一次性授权码，浏览器打开，Google/GitHub 登录）
2. 轮询 `GET /api/auth/cli/status`（带 fingerprintId）直到返回 `user`（含 `authToken`）
3. 指纹：`"enhanced-" + 确定性哈希(账号标识)`，**同一账号必须永远同一指纹**（freebuff2api 用 FNV-1a 派生；官方用硬件序列号/MAC 哈希）
- 本机 `~/.config/manicode/credentials.json` 结构：`{default: {id, name, email, authToken, fingerprintId, fingerprintHash}}` —— **插件可直接读取复用**。

### 3.2 session 生命周期（额度按「创建 session」扣，1 小时有效）
- `GET /api/v1/freebuff/session`（头 `x-freebuff-include-unused-rate-limits: 1`）→ 查当前 session，同模型直接复用；响应含 `status: active|queued|banned`、`instanceId`、`model`、`rateLimitsByModel`（额度快照）、`retryAfterMs`、`uid`。
- `POST /api/v1/freebuff/session`（头 `x-freebuff-model: <session model>`、`x-freebuff-instance-id: <预生成 UUID>`、`Content-Type: application/json`，**无 body**）→ 创建；`queued` 时轮询 GET（1.5s × 8 次）。
- `DELETE /api/v1/freebuff/session`（头 `x-freebuff-instance-id`）→ 关闭。
- 实测注意：`multi-session:1` 创建的实例 chat 会 428，必须用单会话 + 预生成 instance-id。

### 3.3 agent-runs 生命周期（chat 校验 run_id 存在）
- `POST /api/v1/agent-runs` `{action:"START", agentId, ancestorRunIds:[]}` → `runId`
- 主 run（如 `base2-free-deepseek-flash`）+ 子 run（`context-pruner` agent，ancestor=[主 runId]）
- `POST /api/v1/agent-runs/<runId>/steps`（record_step）、`POST /api/v1/agent-runs` `{action:"FINISH"|"CANCEL", runId, ...}`（可跳过，run_id 只校验存在性，可缓存 10 分钟复用）

### 3.4 chat（上游强制流式，OpenAI Chat Completions SSE）
`POST /api/v1/chat/completions`，头：`Authorization` + `x-freebuff-instance-id: <instanceId>` + `Content-Type: application/json`（**不要**带 `x-freebuff-acting-user-id`，带了反而 409 session_superseded；桌面版默认也不带；UA 用默认 fetch 或 `Freebuff-CLI/<ver>` 用于广告接口）。

请求体关键字段（全部经过官方 `hasFreebuffRootSystemPromptOpening` 等服务端校验）：
- `model`: 上游模型 id（如 `deepseek/deepseek-v4-flash`）
- `messages`: 所有 system 消息**必须以 `You are Buffy, the strategic coding assistant.` 字节级开头**（没有则注入前缀，保留原内容），system 带 `cache_control:{type:"ephemeral"}`；没有 system 则 unshift 一条纯 Buffy
- `stream: true`（上游强制）
- `stop`: `['"cb_easp"']`（cb_easp = `endsAgentStepParam`，官方工具常量；无 stop 时补默认）
- `provider: {data_collection: "deny"}`
- `tools`: 带工具时必须混入官方白名单签名工具 `end_turn`（`{type:"function",function:{name:"end_turn",description:"Signal the end of the current task.",parameters:{type:"object",properties:{}}}}`），否则被判 `foreign_toolset` 拒绝/降级
- `codebuff_metadata`: `{freebuff_instance_id, trace_session_id(UUID), run_id, client_id(会话级稳定指纹), cost_mode:"free"}`
- 可选透传：`temperature/max_tokens/stop/tools/tool_choice/reasoning_effort(按模型档位 clamp)/response_format/seed/...`
- reasoning effort 官方表：`deepseek-v4-flash: [low, high, max]`（无 medium）、`deepseek-v4-pro: [high, max]`，超出 clamp-down 不拒绝
- 上游 SSE 与 OpenAI 兼容（`choices[].delta.{content, reasoning_content, tool_calls}` + `finish_reason` + `usage` + `[DONE]`），可能包一层 `{data:{...}}`（需 unwrap）

### 3.5 客户端行为链（合规模仿，失败静默）
- 广告：`POST /api/v1/ads`（body `{provider:"gravity", sessionId:UUID, surface:"waiting_room", device:{os,timezone,locale}, userAgent:"Freebuff-CLI/0.0.138"}`，UA `Freebuff-CLI/0.0.138`）→ 有 `impUrl` 再 `POST /api/v1/ads/impression` `{impUrl, mode:"free"}`；30 分钟节流
- 签到：`GET /api/v1/freebuff/streak`
- 用量：`POST /api/v1/usage` `{fingerprintId}`（30 分钟节流）

### 3.6 硬约束与已知坑
- **免费模型要求 US 出口 IP**（完整模式国家清单见 freebuff.com；CF Workers 因美国出口被社区当跳板；本地客户端建议配美国代理节点）
- **单账号同时只能一个在线实例**（`428 waiting_room_required` / `409 session_superseded`）；上游免费通道并发 >1 出问题 → **必须全局串行队列 + 300ms 间隔**
- **配额池（worker.js v1.7.0 注释，2026-08-10 实证）**：
  - PREMIUM 池：共享 6 次/天（m3 / v4-pro / luna / laguna-s-2.1 / muse-spark / greg-2 等）
  - STANDARD 池：**浏览器/Web 端 6 次/天**（Flash / MiMo 2.5）——官方注释原话 "The CLI keeps these models UNLIMITED; browser surfaces cap fresh sessions to deter automated churn"，但 **CLI 协议已被官方封堵（`free_mode_cli_required`）**，桌面版/Web 协议下 Flash 同样受 6 次/天限制
  - GLM 5.2 独立池（referral 解锁）
  - 桌面并发桶：premium 1 并发 / Flash+MiMo 3 并发 tab / limited 层 1 slot
  - 单号串行日上限 ≈ Premium 6 + Flash 6（太平洋日 07:00 UTC 重置）；额度按「创建 session」扣，1 小时有效，期内多轮对话不重复扣
  - ⚠️ 因此早先 README/freebuff2api 摘要里 "Flash 无限量" 的说法不准确：对桌面/Web 协议路径实际是 6 session/天/账号；本插件默认单账号低并发，session 复用最大化利用率
- 账号状态终态：`status: banned` 所有接口返回，**封禁不可恢复**
- CF Workers 边缘标记（`cf-worker`/`cf-ray`）会被官方识别、显著增加封号风险 → **本地/自建 VPS 运行是安全姿势**，本方案天然满足
- 空流（`[DONE]` 前无数据）= session 脏状态：删实例强制重建同模型 session 重试一次
- 非流式请求上游 45s 聚合超时（本方案无需）

## 5. DSH 模型提供方接入点（代码级确认）

### 5.1 `ctx.llm` 服务（`@deepseek-ai/dsh-llm`，版本 rc.6）
- `llm.registerAdapter(providers: string[], adapter: LlmAdapter)` → 注册路由，返回带 `.replace()` 的句柄，fiber 销毁自动注销；重复 provider 抛 `DUPLICATE_ADAPTER`
- `llm.registerConfigurableProviders([{provider, displayName, settingsNs, settingsPath}])` → 出现在 Web 模型设置页
- `llm.listProviders()` / `llm/adapters-updated` 事件（拓扑通知）

### 5.2 `LlmAdapter` 接口（实现即提供方）
```ts
abstract class LlmAdapter {
  providerInfo(provider): { id /* 必须 === provider */, name }
  providerRetryPolicy(provider)?: RetryPolicy | undefined
  listModels(provider): Promise<ModelInfo[]>   // 顾问性目录
  resolveModel(provider, model, signal): Promise<{
    provider, id, name, inputModalities: ['text'],
    context: { contextWindow }, defaultMaxTokens,
    reasoning?: { efforts: ReasoningEffortId[], defaultEffort }
  }>
  async *stream(options): AsyncGenerator<StreamChunk>  // 必需
}
```
- `stream(options)` 收到的 harness 请求：`{provider, model, messages, system, tools, temperature, maxTokens, stop, reasoningEffort, purpose('chat'|'session-title'|'compaction'|...), sessionId, signal}`
- 产出的 `StreamChunk`：`block-start/block-end`（text/reasoning/tool-call）、`text-delta`、`reasoning-delta`、`tool-call-delta`、`usage`（inputTokens/outputTokens/cacheReadTokens/reasoningTokens）、`finish`（reason: stop|tool-calls|max-tokens|error+code）
- **契约要求**：每个 wire 请求必须带 `attributionHeaders()`（dsh-llm 导出）
- 错误：抛 `LlmError(message, code, {status, providerRetryAfterMs, requestId})`；常用 code：`AUTH`/`RATE_LIMIT`/`QUOTA_EXCEEDED`/`CONTEXT_WINDOW_EXCEEDED`/`TRANSPORT`/`TIMEOUT`/`ABORTED`/`INVALID_REQUEST`/`SERVER`/`MISSING_CREDENTIAL`
- SSE 解析：`eventsource-parser` 的 `EventSourceParserStream`（dsh-llm-deepseek 同款）

### 5.3 模板与装配
- **模板 = `dsh-llm-deepseek`**（lib/index.js 781 行，含 serialize/translate/adapter/apply 四段，逻辑可几乎整体复用）：
  - `apply(ctx, config)`：`ctx.llm.registerConfigurableProviders([...])` + `ctx.llm.registerAdapter([PROVIDER], adapter)` + `installSettingsSection(ctx, NS, Config, config, {setSource, onChange})`（settings 热更新）
  - 配置：`{apiKeyEnv(credentialRef), baseURL, models 目录, maxTokens, defaultContextWindow, streamIdleTimeoutMs, retryPolicy}`
  - 凭证：`ctx.credentials.resolve(credentialRef)`（Web 模型页写入）或启动环境
- **装配方式**：base bundle（`dsh-base/cordis.patch.yml`）以插件行 `- id: llm-deepseek / name: '@deepseek-ai/dsh-llm-deepseek'` 挂载；本地自定义插件走 web profile 的 `bundles` 列表（`~/.dsh/profiles/web/package.json`）+ 超级模组注入器（`dev_inject_plugin`）或 `link:` 依赖 + 重启
- 本地插件 import 模式已验证：dsh-super-injector 直接 `import { LlmAdapter, ... } from '@deepseek-ai/dsh-llm'`（profile node_modules 里有完整 @deepseek-ai 依赖树）

## 6. 推荐方案：dsh-freebuff 插件包

```
dsh-freebuff/
├─ package.json          # name: dsh-freebuff（或 @scope/...），peerDeps: @deepseek-ai/dsh-llm
├─ tsconfig.json
├─ build.sh              # DSH_CHECKOUT 探测 + tsc 编译（超级模组生产线标准）
└─ src/
   ├─ index.ts           # apply(ctx, config)：注册 provider `freebuff` + 设置面板
   ├─ client.ts          # FreebuffClient：协议实现（auth/session/run/chat/ads/streak/队列）
   ├─ adapter.ts         # FreebuffAdapter extends LlmAdapter：serialize + translate（抄 dsh-llm-deepseek 结构，改 wire 层）
   ├─ config.ts          # Schemastery 配置 schema
   └─ types.ts
```

### 6.1 职责划分
| 模块 | 内容 |
|---|---|
| `client.ts` | 串行队列（300ms gap）→ session 缓存复用（剩 >60s 复用）→ agent-runs 链（10min 缓存）→ `chat/completions` 流式请求 → SSE 读出（unwrap `{data}`）→ 428/409 重建重试一次 → 429/配额冷却；广告/streak/usage 行为链（30min 节流）；`GET /api/v1/me` 健康探测 |
| `adapter.ts` | harness 消息 → 上游 payload（Buffy 前缀注入、cb_easp stop、end_turn 签名、codebuff_metadata、reasoning clamp、tools 透传）→ 上游 SSE → harness StreamChunk（复用 dsh-llm-deepseek 的 translate 逻辑）→ LlmError 映射 |
| `config.ts` | `{accounts, baseURL, upstreamProxy, models, maxTokens, contextWindow, streamIdleTimeoutMs, retryPolicy}`；凭证支持三种来源：自动读 `~/.config/manicode/credentials.json`（**默认**，本机已登录）、配置/环境变量、多账号逗号分隔 |

### 6.2 关键设计决策
1. **token 默认自动复用本机 CLI 凭证**（`~/.config/manicode/credentials.json`），零配置即可用；多账号数组轮换+冷却（照搬 worker.js 策略）。
2. **全流式**：harness 的 chat / session-title / compaction 全走 `stream()`，天然规避上游强制流式问题；会话标题与压缩用小 maxTokens。
3. **代理支持**：freebuff 免费模型需 US 出口。Node fetch 不自动走代理 → 提供 `upstreamProxy` 配置（支持 http/https 代理，实现可复用 freebuff launcher http.js 的 CONNECT 隧道代码或 undici ProxyAgent）；默认读 `HTTPS_PROXY` 环境变量（本机 10808 端口是混合代理，若节点为美国则开箱即用；非美国节点会落入受限模式，需提示）。
4. **模型目录**：主推 `deepseek/deepseek-v4-flash`（displayName 如 "Freebuff DeepSeek V4 Flash"），可配置启用 `deepseek-v4-pro`/`minimax-m3`/`gpt-5.6-luna`/`mimo-v2.5`；`resolveModel` 暴露 reasoning efforts（flash: low/high/max，default high）。
5. **单实例并发纪律**：全局串行队列 + session/run 缓存（同 worker.js），杜绝同账号并发顶号。
6. **UI**：`registerConfigurableProviders` 让 freebuff 自动出现在 Web 模型设置页；可加一个设置 section 显示账号健康度/配额/当前 session（可选，二期）。
7. **错误映射**：428/409→重建重试；429/额度→`QUOTA_EXCEEDED`+`providerRetryAfterMs`；401→`AUTH`（提示重新登录 CLI）；banned→`AUTH` 级错误并日志警告。
8. **合规与 ToS**：README 明确声明仅供学习、有封号风险、勿商用/滥用；默认单账号低并发（适配器串行已天然温和）。

### 6.3 许可

- 若以官方源码（MIT）+ 协议事实独立实现 → 可 MIT（推荐路径：用 worker.js 做行为对拍/验证，不复刻代码；translate/serialize 参考 dsh-llm-deepseek（同样 MIT 系））。
- 建议：本项目先以 **MIT** 独立实现，代码注释标注协议事实来源；若需直接搬运 worker.js 段落则整体转 AGPL-3.0（二选一，实施时定）。

## 7. 风险清单
| 风险 | 等级 | 对策 |
|---|---|---|
| 反代违反 freebuff ToS，账号封禁（终态） | 高 | 仅学习自用；默认低并发；不商用；README 声明 |
| 免费模型需 US 出口，非美节点 = 受限模式（6 session/日） | 中 | upstreamProxy 配置 + 启动时探测提示 |
| 单账号并发顶号（428/409） | 中 | 全局串行队列 + session 缓存 + 重建重试 |
| 上游协议/校验变更（Buffy 前缀、工具签名、指纹） | 中 | 协议层独立封装；跟随官方源码与社区更新；免费模型用 `data_collection: deny` 等合规字段 |
| 会话标题/压缩把 Buffy 前缀污染进对话 | 低 | 前缀只加在发给上游的 wire 层，translate 回 harness 时剥离？—— 需实测：上游可能回显。处理：wire 层注入，harness 消息不回写（结论：harness 收到的只有 assistant 内容，system 不回传，无污染） |
